# rc.11 — текущая техническая проверка

03.11.2026. Код rc.11 использует чистый закреплённый Alpine как корневую базу PostgreSQL и одноразового frontend-сборщика. PostgreSQL 17.11 устанавливается из подписанных APK; официальный Node 24.22.2 musl загружается с проверкой полного SHA-256 архива и бинарника. Из архива Node извлекаются только executable и LICENSE. Старые контейнеры PostgreSQL/Node с gosu и bundled npm больше не являются входами сборки. Backend/worker остаются Python. Пять именованных rootfs-параметров сохранены, PostgreSQL и Node используют один Alpine digest.

Подтверждено на 03.11.2026: 283 теста на настоящем PostgreSQL, 0 failures/errors/skipped; все три штатных `security_scan.py --strict` (base/prepared/final) прошли. У API/worker находок нет, у PostgreSQL находок нет; у одноразовых npm-инструментов остаются 3 Medium, без исключений CVE. Проектные npm-зависимости: audit при чистом `npm ci` — 0 vulnerabilities. TypeScript, ESLint, компонентные регрессии, production build, Ruff, Bandit Medium/High, Django deployment check, migration drift, OpenAPI и generated response types проверены.

На свежем стенде rc.11 выполнен HTTPS workflow трёх ролей через Nginx: 150 импортированных сотрудников, тёзка, CSV/PNG→JPEG/PDF/DOCX, CSRF/пароль/MFA, приватность, две редакции/исходные байты, поиск, новости/просмотры/корзина и отзыв сеанса. Live AV/OCR pipeline прошёл с настоящим ClamAV, EICAR не допущен в парсер. На окончательных образах повторно прошли live pipeline и восстановление: 14 бизнес-инвентарей и файлы совпали, прежние пароль/MFA и исторические редакции работают, старый сеанс отвергнут. Все внешние входы и worker источника остановлены на всём интервале. Длительность 36,67 с относится только к синтетическому стенду. Проверены байты 62 Python-файлов API, 65 worker и всех пяти frontend-файлов вместе с provenance: совпадают с checkout/комплектом. Разница времени/Node-версии двух независимых build stamps выявлена отдельно; упаковывается точный stamp контейнерной сборки после проверки всех source/artifact-хешей. Это не обход provenance.

Отдельная предварительная миграция upstream-build PostgreSQL 17.11 → signed-APK PostgreSQL 17.11 выполнена через зашифрованный dump/restore и отдельные тома: 14 бизнес-инвентарей совпали, исходные файлы, пароль/MFA и история редакций сохранены, старый сеанс отозван. После переноса прошла настоящая AV/OCR/публикация/поиск. Это один Docker Desktop-хост, не второй физический сервер или договорный RPO/RTO.

`POSTGRES_STORAGE_FAMILY=postgresql17-apk-alpine3.24` создаётся конфигуратором автоматически. In-place update от upstream-сборки к APK-сборке запрещён, даже при одинаковом major. Подписанный HMAC manifest новых копий содержит storage family; автоматический restore при несовпадении или отсутствии семейства отклоняется до изменения сервисов. Старые копии восстанавливают в соответствующем старом окружении; межсемейный перенос выполняют как отдельную проверенную логическую миграцию, не редактированием manifest и не подключением прежнего PGDATA к новому бинарнику.

Браузер rc.11: обычный сотрудник/историческая редакция, HR пароль/MFA и сохранение новости с перезагрузкой, счётчик RU/UZ, ADMIN пароль/MFA, аккаунты и состояние PostgreSQL/очереди: PASS. Первичная смена пароля, подключение MFA и новые credentials через управляемый браузер не выполнены: требуют участия пользователя; HTTP-протокол проверен.
