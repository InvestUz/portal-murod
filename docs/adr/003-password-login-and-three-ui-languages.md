# ADR 003 — парольный вход и три языка интерфейса

Решение владельца: 03.11.2026, Asia/Tashkent.

Владелец при ручном просмотре явно потребовал: «ввёл логин и пароль и зашёл и всё, больше ничего не надо». Это последнее решение заменяет прежнее требование обязательного MFA и первой смены выданного пароля.

- Стандартный режим: REQUIRE_MFA=none, REQUIRE_PASSWORD_CHANGE=false. Для всех трёх ролей выданные индивидуальные логин/пароль открывают портал без дополнительных экранов.
- Серверные Django-сессии, CSRF, HttpOnly/SameSite/Secure в HTTPS, серверные роли и приватность сохранены. Общих аккаунтов и хранения доступа в localStorage нет.
- Абсолютный срок и таймаут бездействия по умолчанию — 12 часов (SESSION_TTL_SECONDS=43200 и SESSION_IDLE_SECONDS=43200). После выхода, блокировки/архивирования, отзыва сеанса или истечения срока нужен новый вход.
- Существующие OTP-данные не удаляются. Техническая возможность MFA сохранена для отдельного будущего решения ИТ (none / privileged / all); в стандартном интерфейсе MFA не требуется и кнопка сброса MFA скрыта.
- Для прежней установки явные значения окружения сохраняются. Переход на новое согласованное поведение требует установить указанные четыре параметра; старый REQUIRE_MFA=all не превращается в none молча.

По последующим замечаниям владельца добавлены: заполненные HR-шаблоны XLSX на RU/UZ/EN с защитой от импорта примеров; «Назад» и «Наверх»; English как третий язык интерфейса с сохранением в аккаунте и браузерной настройке. Имена/оригиналы документов не переводятся автоматически. Пользовательские поля locale допускают en; миграция 0007 изменяет только допустимые значения поля и не удаляет данные.

Это изменение политики продукта, а не исключение CVE или подмена серверной авторизации демонстрационной. Linux-установка и корпоративные DNS/TLS/VPN остаются задачей ИТ по решению владельца.
