- AES-GCM/HMAC-копия PostgreSQL и файлов восстановлена в независимые тома. Все 14 бизнес-инвентарей совпали до входа в целевую систему; файлы проверены. Старый сеанс отклонён, прежние пароль/MFA и обе редакции сохранены. На всём интервале копирования/восстановления исходные API, worker и входы остановлены. Измеренные 36,61 с на повторе окончательных рабочих образов — длительность маленького синтетического сценария, не договорный RTO компании.
- Браузер на настоящем Python backend: HR создал/изменил сотрудника и фото; проверены даты, две редакции PDF/DOCX и побайтовые скачивания; редактор новости, даты, публикация, корзина/восстановление. Обычный сотрудник не видит скрытый мобильный/год рождения и HR/admin-навигацию; поиск скрытого телефона не раскрывает коллегу. Администратор: список аккаунтов, роли, блокировка архивного аккаунта, экран состояния. Проверены 390px каталог и 1440px администрирование. Браузер использует отдельный loopback HTTP test-mode API; это не проверка доверия браузера к production TLS.

Строгий скан неизменённых upstream-баз от 03.11.2026: PostgreSQL 25 High/1 Critical (gosu/Go), Node 6 High (bundled npm), Python 5 Medium/1 Low (pip); Nginx и ClamAV без находок. Общий gate остаётся FAIL. Подготовленные PostgreSQL/frontend-tools прошли свои проверки, но это не отменяет красный upstream gate. Конечные API/worker до обновления pip имели 0 High/0 Critical и по 5 Medium/1 Low. Обновление pip 26.3 убрало прежние находки, но выявило High во вложенном setuptools; этот неудачный кандидат сохранён в отчёте. В окончательных API/worker pip и ensurepip полностью удалены после установки hash-pinned зависимостей. Проверочный target отдельно получает dev-инструменты. Окончательные рабочие образы просканированы: находок нет; Tesseract 5.5.4 и его происхождение отдельно инвентаризированы. Повторные native-тесты, live pipeline и восстановление прошли. CVE-ignore, снижение severity и исключения не добавлены.

В браузере дополнительно прошли CSV/XLSX через настоящий AV, preview/commit, обязательное решение по совпадению, явный пропуск и отдельное создание тёзки. Собственный мобильный, его видимость, этаж и кабинет сохранились после полной перезагрузки. Искусственный обрыв связи выделенного браузерного API с тестовой БД показал безопасную ошибку и Retry; после возврата сети Retry восстановил экран без перезагрузки. Не заявляется исчерпывающее покрытие всех admin-изменений, remapping/update-by-number в браузере, клавиатуры и всех RU/UZ-состояний. Первый пароль и подключение MFA проверены HTTP; изменение новых credentials через управляемый браузер требует передачи управления пользователю, поэтому браузерный PASS здесь не заявлен.

Windows Docker Desktop Linux/amd64 имеет 10,7 ГиБ памяти. Стандартный acceptance требует Linux-хост и минимум 12 ГиБ; его host guard не обходился. Настоящая установка portalctl на поддерживаемом сервере, независимый пентест, второй физический сервер/RPO/RTO, корпоративные DNS/TLS/VPN и нагрузка на целевой машине остаются отдельными условиями. Привязки тестовых web-входов только loopback; PostgreSQL/AV/worker наружу не опубликованы.

## Отказы и ограниченная HTTP-нагрузка

Реальный ClamAV остановлен и запущен только в собственном стенде. Во время отказа PDF остался недопущенным (ANTIVIRUS_UNAVAILABLE), скачивание получило 403. После запуска настоящего engine и явного retry файл прошёл сканирование, исходные байты совпали. Подпись/свежесть баз не обходились.

У тестового HTTPS-входа устранена задержка Windows IPv6→IPv4: добавлена привязка второго loopback, публичных адресов нет. Неограниченный burst получил 429 от неизменённого Nginx limiter. При ограничении каждого из 1/8 клиентов до 1 запроса/с выполнено 144 HTTPS-запроса без ошибок: p95 при 8 клиентах 173,93 мс, p99 434,84 мс. Один синтетический аккаунт, ограниченный поток, не подтверждение 150 одновременных сотрудников за общим NAT. Текущая per-IP политика 10r/s требует отдельной проверки на реальной офисной/VPN-топологии.

Дополнительная попытка проверить generated response types непосредственно в минимальном runtime-image вернула ошибку отсутствующего frontend-source. Эта build-time команда предназначена для исходников/verification target; соответствующая проверка на исходниках прошла. Runtime Django deployment/migration/OpenAPI проверки и отсутствие pip/ensurepip подтверждены отдельно. Frontend-исходники ради этой команды в production API не копировались.

03.11.2026 официальный registry всё ещё возвращает те же закреплённые digest postgres:17-alpine3.24 и node:24-alpine3.24. Замена pin на новый подтверждённый upstream с исправлениями сейчас не выполнена; обход строгого gate не добавлялся.
