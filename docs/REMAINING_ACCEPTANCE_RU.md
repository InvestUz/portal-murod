# Приёмка на сервере компании — зона ИТ

Актуально для 0.3.0-rc.12, 04.11.2026. Разработка и локальная проверка: [текущий статус](RC12_TECHNICAL_STATUS_RU.md), [машиночитаемая сводка](verification/2026-11-03-rc12-summary.json). Все пять замечаний владельца закрыты на локальном backend. Простой вход логин/пароль, UZ/RU/EN, сессия 12 часов; прежние обязательные MFA/первая смена отменены решением владельца: [ADR 003](adr/003-password-login-and-three-ui-languages.md).

По прямому решению владельца следующие этапы выполняет ИТ-служба:

1. Полная штатная установка и приёмка на отдельном Linux x86_64 стенде: Python 3.10+, OpenSSL, Compose 2.24+, 4 vCPU, 12 ГиБ RAM и 40 ГиБ свободного места. Из portal/: `python3 operations/acceptance.py --work-dir /var/tmp/toshkent-rc12-acceptance-01 --keep-lab`. Каталог новый; не использовать рабочую БД компании. На Windows host guard останавливает эту общую команду; отдельные PostgreSQL/HTTPS/AV/restore проверки выполнены без обхода защиты.
2. Реальные DNS/TLS/офисные и VPN CIDR/ACL, отдельное хранение recovery-ключа, место копий, мониторинг и оповещения. Синтетические аккаунты/ключи/сертификаты разработчика в поставку не включаются.
3. Приёмка реального OCR-корпуса, нагрузка/отказы на целевой машине, восстановление на втором физическом сервере и фактические RPO/RTO. Вторые локальные тома этого не доказывают.
4. Независимый пентест/ретест и эксплуатационный допуск. Собственные сканы не являются независимым пентестом. Три Medium одноразового npm builder остаются видимыми; все строгие High/Critical gates пройдены, исключений нет.
5. Браузерная матрица на корпоративной сети/сервере: [инструкция](BROWSER_ACCEPTANCE_RU.md). Локальные результаты и их точная область приложены; это не автоматический PASS каждой строки на будущем сервере.

`productionApproved=false` сохраняется. Это внешняя приёмка и подключение готового комплекта к инфраструктуре компании, а не обещание уже выполненного развёртывания.
